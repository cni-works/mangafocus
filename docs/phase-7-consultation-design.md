# Phase 7A AI相談資料 設計方針

## 目的

Manga Libraryに登録した1冊について、漫画情報、既存の解析集計、相談テーマ、ユーザーの補足をプロバイダー非依存のMarkdownへ整理する。プラグインから外部AIへ自動送信せず、利用者がプレビューを確認してコピー先を選ぶ。

## 画面と処理

漫画解析の選択中Viewerから「AI相談資料を作成」へ移動し、Viewerと解析期間をGETパラメータで引き継ぐ。相談画面は`manage_options`を要求し、生成POSTはnonceを検証する。相談テーマは許可リストで複数選択でき、自由入力は保存せず、HTMLを除去して資料内の引用ブロックへ分離する。

含める情報は解析データ、漫画画像URL、PC／スマホ用コマ情報から選択する。初期状態はすべてONとする。生成結果は読み取り専用テキスト領域で表示し、クリップボードへコピーした結果を画面上で通知する。

## 共通集計

解析画面のHTMLは読み取らない。`ai_manga_viewer_analytics_context()`で期間、Viewerカタログ、主要指標、日別値、ページ到達を組み立て、`ai_manga_viewer_analytics_page_analysis()`で到達人数、到達率、前ページ比、最大離脱を共有する。AI相談側はこの集計済みコンテキストとViewerの保存済みページ設定だけをMarkdownへ変換する。

解析収集がOFFでも既存テーブルに過去データがあれば同じ集計を利用する。データがない場合は「解析データなし」と明記し、画像と設定を中心とした資料を作れる。Viewer表示イベント導入前の期間など、表示数より読書開始数が多い場合は開始率を算出しない。

## 出力と安全性

資料形式には`consultation_context_version`を埋め込み、タイトル、ページ数、期間、Viewer ID、Viewer設定、集計値、読書進行、ページ別状況、最大の到達減少、CTA、画像、自由入力、不明情報、AIへの依頼を順に記載する。Version 2では減少箇所を「前ページ→到達ページ」の区間として示し、前ページ終盤・到達ページ冒頭・ページ送りを確認候補にする。少数データでは原因と断定せず、10セッション未満の注意を自動挿入する。CTA表示回数など未計測の値は作らない。

スマホ用コマ個別指定がOFFの場合は、スマホでもPC用コマを共用する実際の挙動を明記し、`mobileFocusAreas`が0件という保存値だけを欠落として提示しない。ページレイアウト、綴じ方向、最大幅、全画面、ズーム、スクロール補助等もViewer設定として渡す。AIには改善案を即時確認可能な設定、データ蓄積後に判断する仮説、追加情報が必要な事項へ分け、根拠と確度を付けるよう依頼する。

AI相談のメニューと導線は漫画解析がONの場合だけ表示する。Manga Library一覧では「解析を見る」の右に相談資料作成を置き、個別解析画面では漫画編集と相談資料作成を同じ折り返し可能な操作行へ配置する。解析OFF時は過去データを削除しないが、AI相談へのボタンとサブメニューは表示しない。

visitor key、session ID、instance key、匿名識別子、生イベントは出力しない。画像URLはHTTP/HTTPSのみを対象とし、認証情報、クエリ、フラグメント、localhost、予約・非公開IPを含むものを除外する。除外時とAIがURLを参照できない場合に備え、画像をページ順に手動アップロードする案内を出す。

## 後続段階

- Phase 7A: 相談テーマ、自由入力、解析データ、画像URL、Markdown、コピー
- Phase 7B: 需要確認後のAI相談パックZIP
- Phase 7C: 需要が確認された場合だけ外部AI連携を再検討

Phase 7AではZIP、画像ファイルのコピー、外部AI API、自動送信、AI回答保存、Reader Reactions、Search Console・SEO・SNS API、Free/Pro制御を実装しない。
