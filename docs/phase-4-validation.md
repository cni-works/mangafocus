# Phase 4 Manga Library基盤の検証記録

2026-09-27 / 0.2.0-alpha / 作業ブランチ: feature/manga-library-foundation

## 最小実装

- 管理専用のカスタム投稿タイプ`amv_viewer`を「漫画ライブラリ」として登録した。
- ブロックエディターを利用するため`show_in_rest`を有効にし、新規登録時は既存の`ai-manga-viewer/viewer`ブロック1個を固定テンプレートとして配置する。
- タイトル、本文、表紙画像、改訂履歴をWordPress標準機能で保持する。別の漫画編集エンジンは作らない。
- 投稿IDをViewer IDとして利用し、管理一覧へ表紙、タイトル、Viewer ID、ページ数、公開状態、ショートコード、更新日を表示する。一覧はPCで横型カード2列、1100px以下で1列、600px以下で表紙と情報を縦積みにする。表紙は4:3領域へ`contain`で収める。各行はショートコードをそのまま表示し、表示部分のクリックでコピーできる。Viewer IDと更新日で並べ替えられる。
- 管理画面では編集できるが、個別公開URL、アーカイブ、検索結果、ナビゲーションメニューには直接公開しない。
- 通常の保存・削除はWordPress標準の権限、nonce、リビジョン、ゴミ箱処理を利用する。直接配置ViewerのLibrary登録だけは認証済みRESTを使い、`edit_posts`と元投稿の`edit_post`権限を確認する。`publish_posts`権限があれば公開、なければ下書きを作成する。
- 直接配置Viewerからの登録では、ページ、PC／スマホ用コマ、CTA、表示設定をサーバー側の許可リストでサニタイズしてコピーする。先頭ページの既存添付画像を自動アイキャッチとして再利用し、元ブロックへ`libraryViewerId`を保存して重複登録を防ぐ。元ブロックとLibrary Viewerは自動同期しない。
- 自動アイキャッチには追跡メタを付け、先頭ページが変わった場合だけ追随する。利用者がアイキャッチを設定・変更・削除した後は手動扱いとして上書きしない。外部画像URLは取り込まず、一覧・選択UIだけ先頭ページURLへフォールバックし、0ページでは従来のプレースホルダーを表示する。
- `[ai_manga_viewer id="123"]`形式の1冊用ショートコードを追加した。Manga Libraryの投稿IDをViewer IDとして参照し、保存済みの`ai-manga-viewer/viewer`ブロックだけを抽出してWordPress標準の`render_block()`で描画する。
- 一般閲覧者には公開済みViewerだけを表示する。下書き、非公開、予約済みは対象Viewerの編集権限を持つ利用者だけが確認でき、ゴミ箱・自動下書き・別投稿タイプ・無効なIDは空表示にする。
- ショートコードにページ画像や表示設定を複製せず、登録済みViewerの本文を正本として維持する。`render_block()`を通すことで既存のブロックラッパー、描画フィルター、CSS・閲覧用JSの登録経路を共有する。
- Gutenberg向けに「登録済みViewer」ブロック`ai-manga-viewer/library-viewer`を追加した。保存属性は数値の`viewerId`だけとし、漫画本体や表紙URLは設置ページへ複製しない。
- 編集画面では、編集権限で参照できるManga Libraryを更新順に最大100件取得し、表紙・タイトル・Viewer ID・更新日時のカードから1冊選ぶ。アイキャッチURLは専用の読み取り専用RESTフィールドから取得し、WordPressの埋め込み応答差に依存しない。タイトルまたはViewer IDで絞り込み、表紙未設定時はフォールバックを表示する。
- 選択後は表紙、タイトル、Viewer ID、公開状態、更新日時をコンパクトな表紙カードとして表示する。編集画面ではViewer本文を展開せず、公開側で登録元のViewer全体を描画する。選び直しと選択解除を明示し、選択済みViewerが最初の100件に含まれない場合もID指定で個別取得する。
- 選択済みViewerが削除された場合や参照権限を失った場合は、編集画面で理由候補を示して選び直せるようにする。公開側では壊れた参照を空表示とし、別の漫画へ誤って置き換えない。
- 公開側はショートコードと同じ共通参照関数を利用し、登録済みViewerの公開状態、権限、ブロック抽出、アセット読み込みを同じ規則で扱う。

## ローカル検査

- 投稿タイプキー、管理UI、REST対応、非公開ルーティング、表紙対応、固定ブロックテンプレートをPHPテストで確認した。
- 既存の直接配置ブロック、CNI Blocksとの共存、描画互換テストは継続して合格している。
- 独立したモーダル型の表紙選択ダイアログ、100件を超える検索結果自体のサーバー検索・ページ送り、Analyticsはまだ実装していない。選択済みの1冊は100件外でも個別取得して表示する。

## WordPress実機で確認する項目

1. 管理メニューに「漫画ライブラリ」が表示される。
2. 新規追加でタイトル欄、表紙画像、AI Manga Viewerブロック1個が表示され、ブロック自体は削除・追加できないが内容は編集できる。
3. 画像、綴じ方向、全画面、ズーム、コマ設定を保存し、再読込後も維持される。
4. 一覧がPCで横型2列、タブレットで1列、スマートフォンで表紙と情報の縦積みになり、表紙全体、タイトル、編集・削除、Viewer ID、ページ数、公開状態、解析、ショートコード、更新日が表示される。検索、一括操作、コードのコピーとViewer ID・更新日の並べ替えも確認する。
5. 下書き、公開、リビジョン、ゴミ箱、権限ごとの操作がWordPress標準どおりに働く。
6. 登録しただけでは公開側の個別URLや検索結果へ露出しない。
7. Classic Editorまたはショートコードブロックへ`[ai_manga_viewer id="Viewer ID"]`を配置し、公開済みViewerが直接配置時と同じ設定・操作UIで表示される。
8. 無効なID、別投稿タイプ、ゴミ箱、一般閲覧者から見た下書きが空表示になり、編集権限を持つ利用者は下書きを確認できる。
9. 同じページへ複数のViewerを置いても、ページ送り、全画面、ズーム、専用ビューアーが各Viewer内で独立して動く。
10. Gutenbergで「登録済みViewer」ブロックを追加し、編集画面では表紙カードだけが収まりよく表示され、タイトル検索、Viewer ID検索、選び直し、選択解除が動作する。公開側ではViewer全体が表示される。
11. 登録済みViewerを更新すると、参照ブロックとショートコードの双方へ同じ変更が反映される。
12. 投稿内の直接配置Viewerからタイトルを指定してLibraryへ登録し、ページ順、PC／スマホ用コマ、CTA、表示設定、先頭ページ表紙が一致する。Library編集で先頭ページを変更すると自動表紙が追随し、手動設定・変更・削除した表紙は上書きされない。再実行で複製されず、元ブロックの内容が変わらない。
13. 登録後に明示的な切替を選んだ場合だけ登録済みViewerブロックへ置換され、取り消し操作が使える。登録しただけでは直接配置ViewerのAnalyticsを開始しない。

実機確認後、選択UIの件数・検索方法を調整し、Phase 4の完了条件を確認する。複数冊のManga Library一覧ブロックはまだ実装しない。
