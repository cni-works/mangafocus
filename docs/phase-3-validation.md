# Phase 3 通常閲覧強化の検証記録

2026-09-27 / 0.2.0-alpha / 作業ブランチ: feature/viewer-navigation-stability、feature/reader-zoom-pan

## 全画面表示の最小実装

- ブロック設定へ「全画面ボタンを表示」を追加した。保存属性は `enableFullscreen`、既定値はfalse。既存投稿にはボタンを追加しない。
- ONの場合だけ、ページ番号と同じ操作行へ小さな「全画面で読む」を出力する。全画面中は「全画面を終了」へ切り替え、`aria-pressed` で状態を示す。専用ビューアーは独立した主要ボタンとして視覚的な優先度を分ける。
- ブラウザー標準のFullscreen APIを使用する。APIを利用できない環境ではボタンを隠す。
- 全画面中もページ番号、ページ送り、専用ビューアーボタンを維持する。画像は画面高から操作領域を除いた範囲へ収める。
- 全画面中は左右中央へ半透明のページ送り矢印を表示する。綴じ方向に合わせて「次」と「前」の位置・向きを変え、先頭・末尾では進めない側を隠す。既存のページ端ボタンを使い、追加のJavaScript処理は行わない。
- 全画面中に専用ビューアーを開く場合、モーダルを全画面要素の内部に維持する。全画面要素の外側にある `body` へ移して背面に隠れる問題を防ぎ、専用ビューアーを閉じた後も通常ページの全画面状態を維持する。
- 全画面中は「全画面を終了」を大きな主ボタンとして表示し、「専用ビューアーで読む」は小さな副ボタンとして表示する。終了操作を見つけやすくし、2つのボタンの優先度を明確にする。
- 最終ページでさらに次へ進む操作をした場合は全画面を終了する。ページ端クリック、キーボード、スワイプのいずれも共通の次ページ処理を使う。通常表示では従来どおり最終ページの「次」を無効にする。
- Versionを0.2.0-alphaへ更新した。ブロック名、既存属性の意味、Free/Pro制限は変更していない。

## ローカル検査

- エディターJS、フロントJS、ブラウザーテストの構文検査に合格。
- PHP描画テストで既定OFF時の旧描画互換と、ON時のボタン・初期ARIA状態を確認し合格。
- Edgeの幅1200px、390px、320pxでボタンが画面内に収まり、ページ番号と重ならないことを確認した。
- 全画面開始・終了時のクラス、ボタン文言、ARIA状態、画像高、既存ページ送り、専用ビューアーとの共存を確認した。
- Fullscreen APIは自動テスト用の模擬実装で状態遷移を確認した。実ブラウザーのネイティブ全画面を代替する検査ではない。

## 自由ズームとパンの最小実装

- ブロック設定へ「自由ズームと移動を有効化」を追加した。保存属性は `enableZoom`、既定値はfalse。既存投稿へ操作UIを追加しない。
- 100〜300%の＋／−／全体ボタン、ピンチズーム、拡大中のマウス・1本指ドラッグ、`+`・`-`・`0`キーと方向キーに対応した。
- 拡大中はページ端、スワイプ、左右キーによるページ送りを停止する。等倍へ戻すとページ送りを再開する。
- 通常のホイールは記事スクロールへ残し、`Ctrl`を伴うホイールだけをズームに使用する。ページ変更、専用ビューアーへの同期、全画面終了時は等倍へ戻す。
- 自動検査ではPC・スマホ幅で操作UIが収まること、拡大率、ピンチ、パン中のページ固定、リセット後のページ送り復帰を確認する。
- 下配置ではページ番号とズーム操作を同じ列へまとめ、全画面と専用ビューアーを次の操作列へまとめる。通常幅で操作ボタンが3段に分散しないようにし、狭い画面では画面外へはみ出さないことを優先して折り返す。
- ズーム操作の位置は「下（横並び）」「右（縦並び）」「左（縦並び）」から漫画ごとに選べる。既定値は下。右・左はPCで漫画の外側へ縦配置し、画像を隠さない。スマホ・タブレット幅では右・左のボタンを隠し、ピンチ操作を利用する。全画面中だけは表示領域内へ戻す。
- ブロック編集画面でもズームの有効状態と下・右・左の配置プレビューを表示し、公開画面を開く前に設定結果を確認できる。
- 通常時は全画面と専用ビューアーを同じ操作列へまとめ、専用ビューアーを大きな主ボタンとして維持する。全画面中は終了を大きな主ボタンへ切り替え、専用ビューアーを小さくする。
- 拡大中だけ上段の左右端へ小さな三角のページ送りを表示する。タップ領域は44pxを確保し、押すと倍率と移動位置を等倍へ戻してからページを送る。綴じ方向に応じて前後の配置と三角の向きを入れ替え、画像のドラッグやスワイプ自体ではページを送らない。

## 実機確認済み

- 専用テストサイトで、全画面中は終了ボタンが主要操作として表示されることを確認した。
- 最終ページでさらに送ると全画面が終了することを確認した。
- Chromeの公開画面で、スーパーリロード後に自由ズーム操作欄が表示され、`＋`で100%から125%へ拡大し、「全体」で100%へ戻ることを確認した。更新直後はページキャッシュまたは最適化済みアセットが残る場合があるため、検証時は公開URLの再読込状態も確認する。

## 実機で残る確認

1. Escapeによる終了と、終了後のページ位置・キーボードフォーカスを確認する。
2. PC、Android、iPhone/iPadの利用可能な範囲で、縦横回転とブラウザーUIを含む画像の収まりを確認する。
3. 全画面中も左右綴じのボタン、キー、スワイプが正常であることを確認する。
4. 専用ビューアーを有効にした漫画で、全画面表示との切り替えとスクロール復帰を確認する。
5. 自由ズームの＋／−／全体、ピンチ、マウス・1本指ドラッグを確認し、拡大中に意図せずページが送られないことを確認する。
6. PCで右・左配置の＋／−を複数回続けて操作でき、ボタンが漫画の外側にあることを確認する。スマホ・タブレット幅では右・左の操作列が隠れ、ピンチ操作を妨げないことを確認する。

自由ズームとパンの実機確認後に操作範囲を確定し、必要な補正だけを追加する。

## Phase 3追加A：見開き表示

- Viewer属性へ`pageLayout`（`single`／`spread`／`auto`、既定`single`）と`singleFirstPage`（既定true）を追加した。既存Viewerは保存属性がなくても従来の1ページ表示を維持する。
- 保存済み`pages`は1画像＝1ページのまま変更せず、フロントでページindexから表示面を組み立てる。先頭単独、縦長2ページ、横長単独、余った最終ページ単独を同じ処理で扱う。
- `spread`はコンテナ幅600px以上で見開きへ入り、560px未満で1ページへ戻る。`auto`は780px以上で見開きへ入り、740px未満で1ページへ戻る。端末判定ではなくViewer自身の`ResizeObserver`を使う。
- 見開き時の最大幅は`min(親コンテナ幅, maxWidth × 2 + 12px)`とし、上限1600pxとする。単独表示中のページ面は従来の`maxWidth`を維持する。
- 添付画像はWordPressの画像メタデータ、寸法不明画像はブラウザーの実寸を利用し、縦横比1.18以上を横長単独ページとして扱う。
- DOMは論理ページ順のまま保持し、右綴じだけCSSの視覚順を反転する。見開き番号は`2–3 / 10`形式とした。
- 見開き全体を共通`surface`で包み、自由ズームとパンはsurface全体へ適用する。見開き中は従来の1ページ回転演出を使用しない。
- 全画面の見開きは、各ページの縦横比と利用可能高さから実描画幅を求め、`2ページ分の幅 + 12px`へsurfaceを縮めて中央配置する。画面幅を2等分した列の中央へ画像を置くことで生じていた過大な中央余白を解消する。
- コマ読みのPC／スマホ別コマ列はページ単位のまま維持し、通常Viewerとの同期時は対象ページを含む表示面へ移動する。
- AnalyticsのDB・REST・イベント形式は変更せず、表示面に含まれる実ページそれぞれへ`page_reach`を送る。`read_start`は表示面の先頭ページを代表値とする。
- 直接配置ViewerからLibraryへ登録する許可属性へ2属性を追加した。登録済みViewerブロックとショートコードはLibrary内の同じViewerブロックを共通描画する。

### 自動検査

- PHP/JS構文、render smoke、既存browser smoke、Analytics smoke、release smokeを実行する。
- 見開き専用browser smokeで1・2・3・4・5・10ページ、先頭単独ON/OFF、右／左綴じ、横長単独、CTAの論理Tab順、surfaceズーム、ページ到達重複排除、autoヒステリシス、全画面中の幅変更、中央gap、狭幅フォールバックを確認する。

## 見開き設定の選択制御

- 横長判定値`1.18`と表示面の組み立てを`blocks/viewer/layout.js`へ集約し、Gutenbergと公開Viewerで同じ規則を利用する。
- `singleFirstPage`、ページ順、横長単独表示を反映した結果、見開きペアが0組と確定した場合は「見開き」「自動」を選択不可にする。「1ページ」は常に選択できる。
- 画像寸法が未取得で見開き可否を確定できない間は選択を妨げず、「画像情報を確認中」と表示する。WordPress添付メタデータを優先し、取得できない画像だけ元画像の実寸で再評価する。一覧用の切り抜きサムネイルは判定に使用しない。
- 見開きが可能な場合は作成されるペア数を表示する。横長ページと余ったページは単独表示されることも併記する。
- 保存済みの`spread`／`auto`が後から利用不可になっても、属性を`single`へ書き換えない。編集画面で理由を表示し、公開側の従来フォールバックに委ねる。
- Fullscreen API、タッチ、端末回転、テーマ内の実カラム幅、スクロール補助は自動環境だけでは実機操作を代替しないため、専用テストサイトで確認する。

見開き専用のページめくり演出はPhase 3追加B候補とし、Phase 3追加Aの実機確認前には進めない。

## Phase 3追加A-2：pageFocus読書モード

- Viewer属性へ`spreadReadingMode`（`overview`／`pageFocus`、既定`overview`）を追加した。保存属性がない既存Viewerは従来どおり見開き全体を表示する。
- `pageFocus`は全画面のページ送りでのみ使用する。通常のページ内Viewerは常に見開き全体を表示し、全画面へ入ると見開きの組み合わせとDOM順を維持したまま、`focusedPageIndex`の1ページをViewer幅へ自動拡大する。右綴じ・左綴じは視覚配置だけに反映し、送る順序、Tab順、コマ順、Analyticsは論理ページ順のままとする。
- 自動フィットは外側の`focus-layer`、利用者の自由ズーム・パンは内側の`surface`へ適用する。ページ移動時は手動ズームだけを100%へ戻し、pageFocus自体は維持する。
- 自動フィットの上限は通常表示・全画面ともViewer横幅とブラウザー表示高の小さい側で決める。表示高から操作用の128pxを確保し、pageFocusだけでページ下部や操作列が画面外へ押し出されないようにする。
- ページ番号は通常時に`2 / 10`、一時的な「見開き全体を見る」では`2–3 / 10`と表示する。一時全体表示中は見開き内の両ページをAnalytics到達として扱い、通常のpageFocus中は実際に焦点表示した1ページだけを到達として扱う。
- 非表示側ページは`aria-hidden`と`inert`で操作・読み上げ対象から外す。これにより非表示側CTAへTabフォーカスが移らない。全画面、autoの幅切替、専用コマViewerとの往復でも対象ページを維持する。
- 全画面または専用コマViewerを最終ページまで進めて終了した場合は、通常Viewerを先頭へ戻す。途中で閉じた場合は現在ページを維持する。
- 全画面へ入る直前のViewer上端位置を記録し、解除と先頭復帰によって見開きの高さが変わっても同じ画面位置へ戻す。左右配置のズーム操作は全画面中だけ暗色背景へ切り替え、白いボタンが背景へ同化しないようにする。
- 自動検査では同一見開き内と見開き間の移動、右綴じのキー操作、一時全体表示、外側フィットと内側ズームの分離、全画面往復、専用Viewer同期、CTA非活性化、ページ単位到達、auto切替後の位置維持を確認する。
- 本格的な見開きページめくり演出は追加していない。横長判定値`1.18`と既存の表示面構築規則も変更していない。

### 実機で残る確認

1. Gutenbergで`overview`／`pageFocus`を保存し、直接配置、Manga Library、登録済みViewer、ショートコードの各経路で同じ表示になること。
2. 実画像の縦横比、テーマのカラム幅、PC全画面、タブレット回転時に、焦点ページの文字サイズと上下の収まりが自然であること。
3. マウス、タッチ、スワイプ、左右キー、CTA、スクロール補助、専用Viewerとの往復を実機で比較し、意図しないジャンプがないこと。
